## Detalle por área

### Frontend — correcciones de datos (#9)
- **#1 Precio "/persona":** las tarjetas de opciones mostraban un total etiquetado como
  "€/persona" y con bases distintas. Ahora las tres leen `estimated_total` y la etiqueta
  dice "total".
- **#2 Mapeo de n8n (`mapN8nToTripData`):** verificado con harness contra
  `n8n/examples/output-plan.json`:
  - (a) el total del presupuesto ahora **cuadra** (suma de componentes, no `total_usd`).
  - (b) el `area` del hotel ya no muestra **coordenadas GPS** crudas.
  - (c) la **comida** se costea por la duración real del viaje (fechas), no por nº de entradas.
  - (d) el relleno de **check-out** usa el índice del array, no `dayPlan.day`.
- **Crash de itinerario vacío:** el mapper garantiza ≥1 día y `ItineraryTimeline` tolera
  itinerario vacío (antes: `Cannot read properties of undefined (reading 'title')`).
- **Tipado:** se eliminaron los `any` de `route.ts` (interfaces `N8n*`), lo que además destapó
  y blindó dos `undefined` latentes.

### Frontend — calidad y UX
- **#5 Gate de calidad:** `verify.ps1` gana un "Paso 6" que corre `tsc --noEmit` (gate duro) y
  `npm run lint` (informativo). ESLint del frontend bajó de 41 a 31 errores.
- **#7 Toggle de tema:** botón claro/oscuro en la Navbar; activa el CSS `dark:*` existente
  (Tailwind v4 class-based), persiste en `localStorage`, con script anti-flash. Spec:
  `docs/specs/2026-07-04-toggle-tema.md`.
- **#15 Honestidad ante fallos de n8n:** si n8n responde `needs_user_input`/`warnings` (p. ej.
  sin vuelos), el frontend muestra el aviso real en el planner en vez de fingir un viaje con
  datos por defecto. Spec: `docs/specs/2026-07-04-manejo-needs-user-input.md`.

### Backend / integración n8n
- **#8 Conexión frontend ↔ n8n:** se documentó `N8N_WEBHOOK_URL` (la variable que el código
  realmente lee); antes `.env.example` documentaba otra que nadie usaba.
- **Diagnóstico "siempre la misma información":** la conexión funcionaba, pero n8n devolvía
  planes vacíos para muchos destinos y el frontend los enmascaraba con defaults. Dos causas:
  1. **Tabla IATA** con nombres en inglés → nombres en español caían al fallback (3 primeras
     letras): "Valencia" → `VAL` (real `VLC`). Corregido añadiendo ciudades españolas y
     capitales del mundo (~110 ciudades).
  2. **Vuelo de vuelta** fallaba de forma intermitente: la herramienta hacía **una** búsqueda
     round-trip, pero Google Flights devuelve solo la ida + un `departure_token`, y la vuelta
     exige una **segunda** llamada con ese token que el `json_restrictor` eliminaba.
- **#17 Workflow v27:** arregla ambas cosas — herramienta en modo **one-way** (`type=2`) y el
  prompt hace **dos búsquedas** (ida y vuelta por separado). Verificado en el n8n local:
  Valencia→Londres, Barcelona→Roma/Oporto, Madrid→Paris/Dublin, Sevilla→Londres → todos con
  ida **y vuelta**. Aplicado al n8n en marcha y versionado en el repo (workflow + doc + ejemplo).

### Infraestructura / onboarding
- **#18 Stack reproducible por dev:** `docker compose up -d` en un equipo nuevo crea n8n,
  importa credenciales + workflow v27 y lo **publica** (activa el webhook) automáticamente.
  El volumen dejó de ser `external`. Cada dev usa **sus propias** claves de API.
  Gotcha detectado: `n8n update:workflow --all --active` está deprecado en n8n 2.x → se usa
  `n8n publish:workflow --id=<id>`.
- **#19 `ONBOARDING.md`:** guía de entrada (puesta en marcha, pruebas, contribución).
- Guía detallada: `docs/levantar-stack-local.md`. Plantilla: `frontend/.env.local.example`.

## Decisiones tomadas
- **#3 Trips compartibles — APLAZADO.** Además del proxy, los viajes viven solo en
  `localStorage` (sin persistencia server-side), así que "compartir por enlace" sería un
  mini-proyecto (Firestore + spec). No se tocó.
- **#7** → toggle de tema (frente a borrar el CSS muerto).
- Pruebas en equipo → **cada dev con su propio stack Docker y sus propias claves** (frente a
  un n8n compartido vía ngrok).
